# Video point playback and zero-second entry

Explicit video point navigation in PreviewLessonView or the shared LessonContentPlayer carries a transient id/request counter. A selection seeks to that point and requests playback, even from a paused state or when the source change remounts the video. Repeated selection of the current point restarts it. Same-source points retain the video element, rate and mute state. Pending playback retries after metadata, seeked or canplay events; listeners are removed on replacement/unmount. Successful playback confirms the new Study point through the existing callback. Normal page entry and initial/resumed point selection do not autoplay.

The existing preview cutoff check runs before automatic playback; a point outside the allowed preview pauses at the cutoff and opens the access dialog. Existing active Exhibit modal behavior still pauses the lesson. Server Entitlement, Study event validation, completion and maximum-progress rules are unchanged. Failed playback remains controlled by the existing visible player controls without added operation notices.

Migration `017_fix_modeling_life_video_starts` is registered after 016 and declares only `touches: ["courses"]`. The imported first video point in Modeling life Lessons 01 and 02 had `startSeconds: 10`; 017 changes that exact value to zero. Later chapter offsets (412/587/1026/1175 and 1204), video URLs, text, Exhibit definitions, assessments and learner records remain unchanged. Custom first-point offsets other than 10 are preserved. Missing targets and already corrected offsets skip. Duplicate identities fail before writing. The course timestamp advances only on change. ORM transaction/ledger handling and independent replay are idempotent. No DDL or media objects are required; the immutable 008 import remains historical source data.
